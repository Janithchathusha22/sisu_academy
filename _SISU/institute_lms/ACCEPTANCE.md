# Deployment acceptance checks — not yet executed on a Frappe site

Run these against disposable test sites before collecting real payments.

1. Install against the exact Frappe/LMS commits you will deploy. Confirm migration, all custom DocTypes including SOUL Settings and Account Request, module loading, indexes, `/campus`, static assets, CSRF and session login. Test a production build, not Vite demo mode.
2. Provision two sites through one fleet registry. Duplicate institute codes and a second institute on one site must fail. A membership ID from site A must not resolve on site B. Test existing LMS course, file, quiz, assignment, certificate and report URLs across hosts as well as the new portal APIs.
3. Create student, teacher and institute-admin users. Test role routing after login; disable a member and verify both portal APIs and native LMS sessions stop working. Test ordinary roles cannot use `/api/resource/IL Invoice` or other generic DocType endpoints to bypass the portal API.
4. Create a classroom as Teacher A. Teacher B and students must fail every write API for it. Admin may manage it. An unenrolled student must fail detail reads; an enrolled unpaid student must see the profile but no session/media/feedback content.
5. Configure payments.lk test mode and test success, cancellation, failure, raw-body signatures, timestamp windows, mismatched amounts/currency/mode/invoice/checkout, duplicate callbacks and concurrent callbacks. Test idempotent retry, timeout and expired-attempt reconciliation. A browser return URL must not unlock anything. Confirm one settlement/receipt/outbox event. Test PayHere separately only if that optional adapter will be offered.
6. Test installments: initial unpaid locks; paid first installment plus future second installment opens; next due date locks; inclusive grace date opens; expired grace locks; Closed overrides payment/grace; Open requires authorized staff; changes create audit records.
7. Configure approved WhatsApp templates. Verify opt-in and opt-out, deactivated users, language mapping, scheduling/material/announcement/payment events, rate-limit retries and Review after ambiguous timeouts. Confirm provider acceptance does not get labeled Delivered.
8. Connect a teacher's test Google channel. Reject a mismatched/expired/replayed OAuth state. Test a live-enabled and a live-disabled channel. Schedule, sync, bind encoder in Studio, start/end, and play a recording. Test private video account invitation requirements and disabled embedding. Test reconnect after token revocation.
9. Verify classroom/session comment precedence, no posting before session end, disabled comments, invalid session/classroom combinations, and HTML rendered as text. Repeat in the Sri Lanka timezone near midnight.
10. Test Sinhala/Tamil mixed titles and 30-grapheme motivation strings containing combining marks/emoji. Test headline 80/81 and description 240/241 boundaries, 1/5/6 images, invalid file types/oversized files, and news dates at publication/expiry boundaries.
11. Test subscription snapshots with 499, 500, 501 and 528 active students, duplicate students across classrooms, inactive memberships, repeated cron runs, and configured base fee. At 528, the additional fee must be LKR 1,400. Institute collection is manual in this release.
12. Check list pagination beyond 24 classrooms and 50 invoices/members. Test mobile dialogs, keyboard focus, zoom, long multilingual text, slow image/font requests and an unavailable API/provider. Review accessibility contrast at final brand colours.

13. SOUL: reject unauthenticated, inactive and unauthorized configuration calls; verify key never appears in responses/logs/build/local storage. Require HTTPS. Verify input and output moderation failure paths, provider timeouts, quotas under concurrent workers, no automatic retries, output escaping and history clearing on account switch. Keep student AI disabled until deployment/youth data review, actual ZDR configuration and member enablement are complete. Test reduced motion, pause, keyboard movement, drag, viewport clamping and mobile chat.
14. News retention: verify invisibility and daily deletion at 30 days, updates cannot extend creation time, batches continue above 500 expired posts, and shared images/lead records are not erased accidentally. Implement and test campaign deletion on the real backend before enabling that demo workflow in production.
15. International release: verify UTC/IANA conversions, daylight saving, week starts, due dates, RTL forms/dialogs, long translated strings and correct gateway currency. Existing LKR/Colombo backend behavior is a known limitation. Never treat switching the language picker as proof of full translation.
16. New demo workflows require backend implementation before release: public directory identity, verified multi-institute teacher memberships, provider-filtered student aggregation, results imports/audits, paid add-on entitlements and course-enrollment bridge. Test tampered tenant IDs, removed affiliations, removed class enrollments and revocation through both custom and native LMS routes.
17. Results: validate XLSX archive limits, missing/duplicate/foreign student IDs, malformed grades/credits, reviewed replacement, atomic rollback, scan-PDF rejection, learner-only result reads, pagination and institute-specific GPA/classification rules. Published results must remain readable without a paid calculator.

Known release boundaries are maintained in [FEATURE_STATUS.md](FEATURE_STATUS.md). The Platform Owner console and newer features visible in demo mode are not evidence of connected production services. Core upstream assignments/quizzes/certificates remain in their existing Frappe screens. No permanent account-erasure workflow, independent security audit, direct camera streaming, WhatsApp delivery callbacks or automatic subscription collection is completed.

## Cozy study and communication release checks

- On a new student profile, cozy daylight is default. Save dark/accent settings; check readable contrast on every student page and modal, keyboard focus, mobile/RTL, reduced motion and browser-storage failures. Profile preferences are currently browser-local.
- Test countdown, stopwatch, pause/resume, suspended device/reload, one-time completion logging, reset and Save/finish. Breaks must not inflate study totals. Audio requires a click and stops on pause, completion, navigation, expiration and disposal. Quote rotation can be paused or hidden.
- Free timers remain available when Study Plus expires. Production needs server-owned subscription state and approved prices; local demo access cannot authorize a charge or entitlement.
- Verify real email delivery, expiration, one-use codes, attempts/rate limits, other-member denial, changed address, opt-in/out and no login-email mutation. Check escaped class text and that messages target only enrolled active recipients.
- Confirm migration backfills existing notification channel to WhatsApp. Email Queue acceptance is not delivery; monitor bounces/errors and retries. Test worker crashes/concurrency against real MariaDB/Redis.
- Google consent must use only app-created-calendar scope plus identity/email; reject another account, expired/replayed state and wrong member/site. Confirm encrypted tokens never enter a browser response/log/export.
- Test session create/update/cancel/restore, enrollment removal, inactive accounts, timezone offsets, duplicate retries, lost insert responses, provider quota, refresh-token revocation and operator reconciliation of uncertain calendar creation. Disconnect must stop future jobs; retained calendar copies must be explained.
- Complete WhatsApp phone verification and approved template/delivery tests before asserting verified phone ownership. No live delivery is covered by local simulation.

## Document and appearance acceptance

- As a teacher, upload a PDF and an Office document with a matching PDF preview. View-only Office without PDF must fail. Upload a separate downloadable Word worksheet.
- As an enrolled student, read both previews, move between pages and expand Read page text. View-only items have no download control; the downloadable worksheet must match the original bytes.
- Attempt the content API as Guest, another institute, another classroom teacher, removed student and payment-locked student. Deny all unauthorized reads, including direct private-file URLs and generic File APIs. Manager access is scoped to their class.
- Reject mismatched extensions/signatures, traversal filenames, oversized uploads, encrypted/macro OOXML and cross-class file references. Scan uploads and test storage limits/cleanup on staging.
- Toggle light/dark from the header as Admin, Teacher and Student; reload and verify each account's selection. Verify readable document controls and no horizontal overflow at 390 px. View-only does not guarantee copy prevention.
